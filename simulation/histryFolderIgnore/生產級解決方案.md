# 生產級解決方案 - 技術文檔

## 🎯 最終方案: TCP 5762

基於專家技術審核,確認 **TCP 5762** 是最佳解決方案。

### ✅ 為什麼選擇 TCP 5762?

| 特性 | TCP 5762 | UDP 14550 |
|------|----------|-----------|
| **連線型** | ✅ 是 | ❌ 否 |
| **會搶客戶端** | ❌ 否 | ✅ 是 |
| **多客戶端穩定** | ⭐⭐⭐⭐⭐ | ⭐ |
| **適合腳本** | ⭐⭐⭐⭐⭐ | ⭐ |
| **QGC 衝突** | ❌ 無 | ✅ 有 |

### 📊 ArduPilot SITL 端口分配

```
UDP 14550 → QGC (地面站)
TCP 5760  → 開發者端口 1
TCP 5762  → 開發者端口 2 (推薦) ⭐
TCP 5763  → 開發者端口 3 (備用)
```

**關鍵洞察**: TCP 端口是 ArduPilot 開發者的「隱藏標準」,專門用於自動化腳本和工具。

## 🔧 關鍵技術實現

### 1. System ID 隔離

```python
SOURCE_SYSTEM = 254  # Secondary GCS / Script
```

**System ID 分配**:
- `1` = Autopilot
- `254` = Secondary GCS / Script (我們)
- `255` = Primary GCS (QGC)

**效果**: 避免被誤認為 QGC,不會踢人

### 2. 心跳發送

```python
def send_heartbeat(master):
    master.mav.heartbeat_send(
        mavutil.mavlink.MAV_TYPE_GCS,
        mavutil.mavlink.MAV_AUTOPILOT_INVALID,
        0, 0, 0
    )
```

**作用**: 讓 SITL 立刻識別為另一個 GCS 客戶端

### 3. 智能參數更新

```python
def set_param_smart(master, param_name, value, last_value, threshold):
    if last_value is None or abs(value - last_value) > threshold:
        # 僅在變化超過閾值時發送
        master.mav.param_set_send(...)
```

**優勢**:
- 避免無意義重送
- 減少 MAVLink 負載
- 提高穩定性

### 4. 參數語意理解

**SIM_MAG_MOT_*** vs **SIM_MAG_OFFS_***:

| 參數 | 用途 | 特性 |
|------|------|------|
| `SIM_MAG_MOT_*` | 馬達磁場干擾 | 與油門/馬達輸出耦合 |
| `SIM_MAG_OFFS_*` | 純偏移 | 固定 bias |

**建議**:
- 模擬飛行中干擾: 使用 `SIM_MAG_MOT_*`
- 重播黑盒數據: 混合使用或僅用 `SIM_MAG_OFFS_*`

## 🔍 故障排除

### 問題: 無法連接到 TCP 5762

**檢查**:
```bash
# 1. 確認 SITL 已啟動
tmux ls | grep ardu_sim

# 2. 檢查端口
netstat -tuln | grep 5762

# 3. 查看 MAVProxy 輸出
tmux capture-pane -t ardu_sim:SITL -p | grep 5762
```

**解決方案**:
- 確認 `sim_vehicle.py` 有開啟 TCP 端口
- 嘗試備用端口: `tcp:127.0.0.1:5763`
- 檢查 Docker `network_mode: host` 配置

### 問題: 參數設定無效

**檢查**:
```bash
# 在 SITL 視窗執行
param show SIM_MAG_MOT*
```

**可能原因**:
- 參數名稱錯誤 (ArduPilot vs PX4)
- System ID 不匹配
- MAVLink 版本不兼容
